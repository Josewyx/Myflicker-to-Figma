# Inspect → construct → verify

Choose the shortest sufficient read path. An unknown target needs shallow `get_metadata({profile:"summary",depth:1})` discovery. For a known ID or selection, go straight to the necessary target details; do not always read both summary and full. Native properties usually need only bounded metadata; request `get_design_context` when CSS or implementation context helps, with `includeScreenshot:false` for structural work. Summary data is an index, not enough to reproduce a design. Search relevant resources only when the task uses them, and inspect the parent's layout before appending children.

Use query filters and bounded pages for discovery. Follow returned pagination and truncation information; a truncated tree is not a complete inventory. Once found, use explicit IDs and request detailed data only for the affected nodes. Do not repeatedly fetch the entire page, font list or variable collection for a small edit.

When a question asks for a few properties of named descendants under a known frame, a scoped read-only script can find those descendants and return exactly the requested values. Do not retrieve their entire surrounding subtree and several CSS contexts. For preservation during edits, snapshot actual existing labels/bindings; do not invent an expected value and then spend another call repairing that assumption.

For an existing design, return a short internal plan of the affected nodes and intended change. For a new composition, establish typography scale, spacing rhythm, colors, image needs and component reuse. Position new top-level frames away from existing bounds. Respect the requested product rather than forcing a visual template.

Build or modify a coherent subtree in one operation. For a known target and exact requested change, a script can validate current types/values before any mutation, abort on mismatch, load required fonts once, apply related edits, and read back affected properties. Do not add an entire context read solely to satisfy a fixed ritual. Do not add screenshots or exported files to ordinary creation/editing; only take a screenshot when the user explicitly requests one. Avoid a separate model turn for each node. Return newly created IDs and reuse them in subsequent calls; do not recreate by name.

Finish with affected IDs and bounded structural/keyframe readback. The user previews playback and manually exports in Figma. Do not call export_animation, download_assets, node.exportAsync or file-writing helpers for default delivery or verification. Screenshots are only taken on explicit request and do not prove playback or component/variable relationships.

Each use_figma call keeps the current page. Pass pageId from a focused read to bind the target page before writes; otherwise explicitly await setCurrentPageAsync once when needed. Local reads and writes are serialized per connected document. Do not run independent scripts concurrently on the same canvas. A fresh DSH Work session binds the only connected document automatically. Multiple documents require explicit selection. Existing bindings never silently switch after disconnect. The currently selected Figma node may change through human interaction; use explicit node IDs once discovered.

Do not turn a health check into an inventory of fonts, variables, all pages and screenshots. Load only the guide needed for the current operation, reuse already-loaded guidance, and skip repeated images when the relevant design has not changed. For diagnostics, retain actual tool names, elapsed times and errors, omitting private file identities and credentials.

The MyFlicker adapter currently does not expose performance cursor/status arguments from the upstream host. Do not send includeMetrics, metricsSince or metricsDetails to figma_status; only compact is accepted. Canvas tool results now include performance.queueMs and bridgeMs plus available native runtimeMs/exportMs/serializationMs counters. Queue and bridge times are measured at the bridge; native runtime/export counters overlap them and must not be added as independent elapsed times. These numbers exclude model thinking and host rendering. Failed dispatched calls can contain queue/bridge timing without native counters. Use host timing/trace records for end-to-end diagnosis.
